# 다국어 구조와 언어 추가 가이드

English summary: locales are chosen by `--locale`, then `IG_LOCALE`, then the
profile (`config.json`, then `voice.md`), then the text's own language, then
en-US. en-US keeps the existing commands and file locations, while allowing
reviewed bug fixes; other locales add resources under `skills/<skill>/locales/<code>/`
and a code path that dispatches on the locale. Shared code lives in
`skills/ig-i18n/` (no SKILL.md, so it is not a command). The English output is
recorded in `tests/golden/en/` and checked on every test run.

## 한눈에 보기

```

  ig-help/
    SKILL.md                    전체 스킬 목록, 주제별 안내, 특정 스킬 사용법
    locales/ko-KR/guide.md      한국어 도움말과 명령 예시
  ig-i18n/                      공용 코드 (스킬 아님, SKILL.md 없음)
    locales.json                지원 언어 목록, 별칭, 기본 말 속도, 자동 판정 기준
    ig_locale.py                언어 결정, 프로필 읽기, 리소스 경로, config.json 저장
    ig_text.py                  언어와 무관한 측정: 표시 폭, 이모지 묶음, 폭 기준 자르기와 줄바꿈
    ig_ko.py                    한국어 분석: 숫자 읽기, 음절과 쉼, 조사 떼기, 구체 표현
    locales/ko-KR.json          한국어 공용 데이터: 단위, 수사, 고유명사, 조사, 불용어, 쉼 길이
    style-ko-KR.md              한국어 글쓰기 공통 규칙 (모든 스킬이 ko-KR일 때 먼저 읽음)

  ig-human/human_ko.py                    한국어 다듬기와 점검 로직
  ig-human/locales/ko-KR/slop.json        한국어 어휘 (auto, terms, structures)
  ig-*/locales/ko-KR/guide.md             14개 스킬 전부 (콘텐츠 13개 + 도움말)
```

## 언어 결정 순서

`ig_locale.resolve(cli, text)`가 모든 스크립트의 공통 진입점입니다.

1. `--locale` (명시)
2. `IG_LOCALE` (명시)
3. `config.json`의 `locale` (프로필)
4. `voice.md`의 `Locale:` 줄 (프로필)
5. 글의 언어: 한글 음절 / (한글 + 라틴 문자) 비율이 0.3 이상이면 ko-KR
6. en-US

설정 파일 위치는 `~/.claude/instagram/`이고 `IG_CONFIG_DIR`로 바꿀 수 있습니다(테스트가 이걸로 실제 프로필을 피합니다).
프로필 언어와 글 언어가 분명히 다르면(한글 비율 0.6 이상 또는 0.02 이하) 프로필을 따르되 stderr에 한 줄 경고를 냅니다.

스킬(SKILL.md) 쪽도 같은 순서입니다. Claude Code는 `/ig-reel --locale ko-KR 아이디어`에서 명령 뒤의 글을 통째로
스킬에 넘기므로, 각 SKILL.md의 "Language (en-US, ko-KR)" 절이 플래그를 읽고 지운 뒤 스크립트에 같은 값을 넘깁니다.
`swipe.py`만 예외로, 명시 설정이 없으면 줄마다 그 훅의 언어로 읽습니다(한 파일에 두 언어를 섞을 수 있게).

## config.json

```json
{
  "locale": "ko-KR",
  "speech": {"ko-KR": {"spm": 312.4}, "en-US": {"wpm": 172}},
  "platform": {"caption_limit": 2200, "hashtag_limit": 5, "truncate": 125},
  "humanize_allow": ["강력한"]
}
```

- `speech`: `beats.py --calibrate 초 --save`가 씁니다. 손으로 써도 됩니다. CLI의 `--spm`, `--wpm`이 이보다 우선합니다.
- `platform`: Instagram 수치가 바뀌었을 때만. CLI 플래그가 이보다 우선합니다.
- `humanize_allow`: ko-KR 다듬기에서 확인할 표현으로 잡지 않을 말.

## 영어를 지키는 방법

- 영어 리소스와 명령 경로를 유지하고, 한국어 분석은 `if locale == "ko-KR"`로 갈라지는 별도 함수에 넣었습니다.
- 공용 코드(`ig-i18n`)가 없을 때도 영어는 원래대로 돌아갑니다(`try: import ... except ImportError`).
  스킬 하나만 복사한 사용자를 위해서입니다.
- `tests/golden/en/`의 16가지 출력은 원작 v1.0을 출발점으로 검증한 버그 수정만 반영합니다.
  `locale` 키를 제외한 출력 차이를 검사하고, 스킬 하나만 복사한 경우도 확인합니다.
- 스킬 이름과 설명, 언어 가이드, 원작의 게시 권한 규칙과 주요 작업 단계는 유지합니다.
  잘못된 판정이나 비교 기준을 고칠 때는 해당 사용 지침과 기대 출력도 함께 수정합니다.

## 짧은 글과 비교 기준

- 문체 검사의 분량 부족 항목은 `score: null`입니다. 전체 `human_score`도 `null`, 판정은 `INSUFFICIENT`이며
  화면에는 판정 보류로 표시합니다. 확인 가능한 점검은 계속 보여 주고, 짧은 댓글의 반복 재작성은 끝냅니다.
- 스와이프 주 순위는 최근 조회수 중앙값이 있는 행만 사용합니다. 중앙값이 없는 행은 참고 목록이며,
  팔로워 대비 조회수와 중앙값 대비 배수를 같은 순위나 상위 공식 통계에 섞지 않습니다.

## 새 언어 추가하기 (예: ja-JP)

1. `skills/ig-i18n/locales.json`에 항목 추가: 이름, 별칭, 문자 체계, 기본 말 속도.
2. 자동 판정이 필요하면 `ig_locale.detect()`에 그 문자 체계를 추가합니다(지금은 한글 비율만 봅니다).
3. 언어 분석 모듈 `skills/ig-i18n/ig_ja.py`: 말 길이(모라 등), 숫자 읽기, 구체 표현. `ig_ko.py`의 함수 이름을 따르면
   스크립트 쪽 코드를 거의 복사할 수 있습니다.
4. 리소스: `ig-reel/locales/ja-JP/hooks.json`(같은 id 26개, 같은 classify_order), `hookscore.json`,
   `ig-caption/locales/ja-JP/caption.json`, `ig-human/locales/ja-JP/slop.json`.
5. 스크립트 분기: 각 스크립트의 `run`/`analyse`에 `elif locale == "ja-JP"` 경로. 지금 구조에서는 언어마다 분석 경로가
   하나씩 늘어납니다. 언어가 셋 이상이 되면 `run_ko`와 같은 함수들을 언어 모듈 쪽으로 옮겨 등록하는 방식으로 바꾸는 게 낫습니다.
6. 문서: `ig-i18n/style-ja-JP.md`와 도움말을 포함한 14개 스킬의 `locales/ja-JP/guide.md`, 그리고 SKILL.md의 Language 절에 언어 이름 추가.
7. 테스트: `tests/test_ja_*.py`, 그리고 `test_regression_en_ko.py`처럼 같은 장면을 두 언어로 비교하는 쌍.

## 설계상 결정

- **번역이 아니라 재구성.** 한국어 훅 공식은 같은 일을 하는 한국어 문장으로 다시 썼고, 직역이 어색한 이유를 `adaptation`에 적었습니다.
- **점수 공식은 공유, 측정은 언어별.** 다섯 항목, 가중치(평균 60%, 최저 40%), 판정 기준은 두 언어가 같고, 각 항목이 무엇을 세는지만 다릅니다.
  그래서 JSON 키가 같고 스와이프 파일에서 두 언어를 나란히 놓을 수 있습니다.
- **한국어 다듬기는 탐지와 수정을 나눔.** 정규식 치환이 뜻을 바꿀 수 있는 한국어 특성 때문입니다. 자동 수정은 이중 피동처럼
  뜻이 그대로인 것만.
- **가운뎃점과 줄표는 표시만.** 3·1절처럼 맞는 표기가 있어서 자동으로 바꾸지 않습니다.
- **수치는 설정으로.** 2,200자, 해시태그 5개, 잘림 125는 코드에 기본값으로 두고 플래그와 config로만 바꿉니다.
- **추정은 추정이라고 출력.** 한국어 시간과 점수 출력에는 추정, 휴리스틱이라는 말이 들어갑니다.
