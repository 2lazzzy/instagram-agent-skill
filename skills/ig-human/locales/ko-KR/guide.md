# ig-human 한국어 가이드 (ko-KR)

먼저 공통 규칙 `../ig-i18n/style-ko-KR.md`(이 스킬 폴더 기준 경로)를 읽습니다.

## 도구

```bash
python3 humanize.py draft.txt --locale ko-KR -o clean.txt --report   # 안전한 것만 고치고 나머지는 목록으로
python3 detect.py draft.txt --locale ko-KR                            # 다섯 가지 점검
python3 detect.py draft.txt clean.txt --locale ko-KR                  # 전후 비교
```

## 영어와 다른 점: 탐지와 수정을 나눴습니다

영어 humanizer는 상투어를 평이한 단어로 자동 치환합니다. 한국어에서 같은 일을 정규식으로 하면
어미, 존댓말, 뜻이 같이 바뀝니다. 그래서 한국어는 이렇게 나눕니다.

| 구분 | 무엇 | 처리 |
| --- | --- | --- |
| 자동 수정 | 보이지 않는 문자, 둥근 따옴표, 말줄임표 문자, 이중 피동(되어진다, 보여집니다) | `humanize.py`가 고침 |
| 확인할 표현 | 과장 마케팅(혁신적인, 게임 체인저), 번역투(~에 있어서, ~하는 것이 가능합니다), 상투적 도입과 마무리, AI 상투어(결론적으로, 핵심은 바로), CTA 상투어 | 줄 번호와 제안만. 고치지 않음 |
| 구조 신호 | 가운뎃점(·) 나열, 줄표(—), '단순히 A가 아니라 B', 'A, B, 그리고 C', 문장 첫머리 연결어 반복, 같은 말로 끝나는 문장 반복, '~할 수 있습니다' 반복, 요청 반복, 느낌표 남발, 문장 길이 균일 | 줄 번호와 고치는 방법만. 고치지 않음 |

확인할 표현과 구조 신호는 **후보이지 판정이 아닙니다**. 평범한 한국어(통해, 또한 한 번,
합니다체)는 목록에 없고, 반복을 세는 점검은 반복될 때만 걸립니다. 사용자가 늘 쓰는 말이
걸리면 `~/.claude/instagram/config.json`의 `"humanize_allow": ["강력한"]`에 넣으면 빠집니다.

👩‍💻, 👨‍👩‍👧처럼 이모지를 구성하는 연결 문자는 보존하며, 탐지기에서도 숨은 문자로
감점하지 않습니다. 일반 글자 사이의 불필요한 숨은 문자는 계속 검사하고 제거합니다.
URL(프로토콜 없는 `example.com/guide` 포함), 이메일 주소, @멘션은 자동 수정하지 않습니다.

## 고치는 순서

1. `humanize.py --locale ko-KR -o clean.txt --report`
2. 보고서 4번(확인할 표현)과 5번(구조 신호)을 보고 해당 문장을 직접 다시 씁니다.
   - 뜻을 바꾸지 않습니다. 사실, 숫자, 요청은 그대로 둡니다.
   - 의미가 바뀔 수 있는 문장은 고친 안을 사용자에게 보여 주고 확인받습니다.
   - 가운뎃점은 쉼표나 '와/과'로, 줄표는 쉼표, 콜론, 괄호, 또는 두 문장으로.
   - 과장 표현은 지우거나 무엇이 얼마나 달라지는지로 바꿉니다. 숫자가 없으면 `{{내 숫자}}`.
3. `detect.py draft.txt clean.txt --locale ko-KR`로 전후를 보여 줍니다.
4. `판정 보류 (INSUFFICIENT)`이면 구체적으로 지적된 부분만 확인하고 검사를 마칩니다.
   1~3문장 댓글은 그 길이를 유지합니다. 점수를 얻으려고 문장을 늘리거나 반복해서 고치지 않습니다.
   `검토`나 `의심`이면 실제로 측정된 가장 약한 신호를 고치고, 내용이 바뀐 뒤에만 다시 검사합니다.
   통과를 위해 사실을 만들거나 요청받은 형식을 바꾸지 않습니다.

## 다섯 가지 점검 (한국어 측정)

| 점검 | 한국어에서 재는 것 |
| --- | --- |
| 문장 리듬 | 문장 길이(음절) 변동. 한국어는 영어보다 변동이 작아 기준을 낮췄습니다 |
| 구체성 | 어절 100개당 숫자, 금액, 시간, 개수(세 가지), 이름(Claude, 노션) |
| 상투 표현 | 어절 100개당 확인할 표현과 이중 피동 |
| 문자 흔적 | 보이지 않는 문자, 줄표, 가운뎃점 나열, 둥근 따옴표, 말줄임표 문자 |
| 목소리 | 마지막 단어의 다양성, 1인칭과 구어 표현, 구조 신호. 합니다체 자체는 감점하지 않습니다 |

분량이 부족한 항목은 `판단 불가`로 표시하고 전체는 `판정 보류 (INSUFFICIENT)`로 끝냅니다.
JSON에서는 해당 항목의 `score`와 전체 `human_score`가 `null`이며, 임의의 50점을 넣지 않습니다.
전후 초안 중 하나가 판정 보류면 점수 차이를 계산하지 않습니다. 판정 보류는 검사 완료이며
통과도 실패도 아닙니다. 충분히 측정할 수 있는 항목의 개별 결과는 참고할 수 있습니다.

기준값은 영어 패널의 의도를 따랐고, 한국어 탐지기 결과로 검증하지 않았습니다. GPTZero 같은
서비스를 부르지 않고, 그 판정을 약속하지 않습니다. "AI 티 안 남"을 보장한다고 말하지 않습니다.

## 출력

다듬은 글을 먼저, 그다음 점수 또는 판정 보류 이유를 보여 줍니다. 점수만 보여 주지 않습니다.

```
다듬기 완료
자동 수정:   3곳 (이중 피동 1, 둥근 따옴표 2)
직접 고친 곳: 4문장 (과장 표현 2, 가운뎃점 1, 연결어 1)
사람 점수:   23.1 의심 -> 74.0 통과 (로컬 휴리스틱)
```
